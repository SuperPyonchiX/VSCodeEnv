# C++14 コードレビューチェックリスト

## 1. メモリ安全性

### 動的メモリ管理
- [ ] `new`/`delete`の直接使用を避け、スマートポインタを使用（AUTOSAR A18-5-2）
- [ ] `std::unique_ptr`または`std::shared_ptr`を使用
- [ ] `std::make_unique`/`std::make_shared`を使用（AUTOSAR A18-5-2）
- [ ] 生配列の代わりに`std::vector`、`std::array`を使用
- [ ] C言語メモリ関数（`malloc`、`free`）を使用しない（AUTOSAR A18-1-1）

### リソース管理（RAII）
- [ ] リソース（ファイル、メモリ、ロック）をRAIIパターンで管理
- [ ] デストラクタでリソースを適切に解放
- [ ] Rule of Five/Zeroを遵守（AUTOSAR A12-8-1）
- [ ] コンテキストマネージャ（スマートポインタ、RAII）を活用

### ポインタ安全性
- [ ] ヌルポインタチェックを実施（CERT EXP34-C）
- [ ] ダングリングポインタを作らない（CERT MEM50-CPP）
- [ ] Use-after-freeを回避
- [ ] バッファオーバーフローを防止（CERT ARR30-C）

## 2. 型安全性

### 型変換
- [ ] C言語スタイルキャストを使用しない（AUTOSAR A5-0-3）
- [ ] 明示的なキャスト（`static_cast`、`dynamic_cast`、`const_cast`、`reinterpret_cast`）を使用
- [ ] 暗黙的な型変換に注意（AUTOSAR A5-0-1）
- [ ] `auto`を適切に使用（型推論の明確性を保つ）

### const correctness
- [ ] すべての定数に`const`を付与（AUTOSAR A7-1-1）
- [ ] 関数パラメータで可能な限り`const`参照を使用（AUTOSAR A8-4-1）
- [ ] メンバ関数で状態を変更しない場合は`const`を付与
- [ ] `constexpr`を活用してコンパイル時定数を定義（AUTOSAR A7-1-1）

## 3. 例外安全性

### 例外処理
- [ ] throw by value, catch by reference（AUTOSAR A15-5-1）
- [ ] 基底クラスへの参照でキャッチ（`catch (const std::exception&)`）
- [ ] デストラクタから例外を投げない（AUTOSAR A15-5-2）
- [ ] 例外安全性保証（基本、強い、nothrow）を確保（CERT ERR50-CPP）

### エラーハンドリング
- [ ] エラーコードを無視しない（AUTOSAR A0-1-6）
- [ ] 戻り値をチェック（特にメモリ割り当て、I/O操作）
- [ ] 適切なエラーメッセージを提供
- [ ] リソースリークを防ぐためにRAIIを使用

## 4. セキュリティ

### 整数演算
- [ ] 整数オーバーフロー/アンダーフローをチェック（CERT INT50-CPP）
- [ ] 符号付き/符号なし混在演算に注意（AUTOSAR A5-0-1）
- [ ] ゼロ除算を防止

### 文字列・バッファ
- [ ] バッファオーバーフローを防止（CERT STR50-CPP）
- [ ] NULL終端を確認
- [ ] `strcpy`、`sprintf`などの危険な関数を避ける
- [ ] `std::string`を優先的に使用

### 入力検証
- [ ] 外部入力を検証
- [ ] バウンダリチェックを実施
- [ ] サニタイゼーション処理を実装

## 5. オブジェクト指向設計

### クラス設計
- [ ] 単一責任原則を遵守
- [ ] 継承の代わりにコンポジションを検討
- [ ] 仮想デストラクタを基底クラスに定義（CERT OOP52-CPP）
- [ ] インターフェースを最小化（AUTOSAR A10-0-1）

### コピー・ムーブセマンティクス
- [ ] Rule of Five/Zeroを適用（AUTOSAR A12-8-1）
- [ ] コピー不要な場合は`= delete`で無効化
- [ ] ムーブコンストラクタ・代入演算子を`noexcept`に
- [ ] コピー高コストなオブジェクトはムーブを実装

## 6. スレッド安全性（該当する場合）

### 並行処理
- [ ] データ競合を回避（CERT CON53-CPP）
- [ ] 適切な同期メカニズム（mutex、lock_guard）を使用
- [ ] デッドロックを防止
- [ ] スレッドセーフなコンテナを使用

## 7. パフォーマンス

### 最適化
- [ ] 不要なコピーを避ける（AUTOSAR A8-4-1）
- [ ] RVO/NRVOを活用
- [ ] インライン化を検討
- [ ] プリアロケーションを活用（`reserve`など）

### アルゴリズム
- [ ] 標準アルゴリズムを優先（`std::find`、`std::sort`など）
- [ ] O(n^2)以上のアルゴリズムに注意
- [ ] ループの最適化

## 8. 可読性・保守性

### 命名規約
- [ ] 一貫した命名規約を使用
- [ ] 意味のある変数名・関数名
- [ ] マジックナンバーを避け、定数を定義

### コメント
- [ ] 複雑なロジックにコメントを追加
- [ ] 公開APIにDoxygen形式コメント
- [ ] TODO/FIXMEを適切に管理

### コード構造
- [ ] 関数の長さを制限（推奨: 50行以下）
- [ ] 循環的複雑度を低く保つ（推奨: 10以下）
- [ ] ネストレベルを制限（推奨: 4以下）

## 9. テスト

### テストカバレッジ
- [ ] 単体テストが存在
- [ ] エッジケースをテスト
- [ ] 例外パスをテスト
- [ ] モックを適切に使用

## 10. ツール検証

### 静的解析
- [ ] Clang-Tidyでチェック済み
- [ ] Cppcheckでチェック済み
- [ ] コンパイラ警告をすべて解消（`-Wall -Wextra`）
- [ ] AddressSanitizer/ThreadSanitizerでテスト済み
